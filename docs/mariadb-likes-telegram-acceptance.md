# Проверка MariaDB, избранного и Telegram

Дата: 15 ноября 2026. Ветка: `feature/mariadb-telegram-favorites`.

Реализация готова к проверке с настоящим Telegram-приложением. **Полная единая
приёмка ТЗ пока не завершена:** в окружении нет Client ID/Secret, зарегистрированного
HTTPS callback и тестовых Telegram-аккаунтов. Реальный вход и физические устройства
не проверялись; ниже они отделены от автоматических проверок. PR в рамках задачи
не создавался; этот отчёт можно использовать как результаты проверки в PR.

## Выполненные проверки

- `DB_PORT=3307 DB_PASSWORD=<test password> TEST_DB_NAME=openmusic_test .venv/bin/python -m pytest -q backend`
  — **27 passed**. Реальная MariaDB **11.4.8**, чистая схема и повторное применение
  миграций. В тестах используются локальные RSA-ключи вместо Telegram.
- Backend: PKCE S256 и Basic auth code exchange, правильный и неверный state,
  cookie привязки браузера, истёкший state, повторный и одновременный callback;
  поддельная подпись и неверные `iss`/`aud`/`exp`/`sub` отклоняются.
- Backend: повторный вход с тем же `iss`/`sub` возвращает прежнего пользователя;
  случайные токены сессий хешируются; проверены срок, отзыв, HttpOnly, Lax и
  production Secure. CSRF проверяет Origin и токен сессии. Callback query
  исключается из uvicorn access log.
- Backend: изоляция двух аккаунтов и двух сессий одного аккаунта, гостевой `401`,
  демотреки/YouTube/альбомы, независимость альбомов, 16 параллельных PUT,
  идемпотентные PUT/DELETE, неизменность даты повторного PUT, регистр ID,
  пагинация и валидация метаданных. Аудиоссылки/user_id в PUT запрещены.
- Backend: новая копия приложения в отдельном Python-процессе читает прежние
  сессию и избранное. Реальная ошибка подключения и искусственный отказ БД
  возвращают `503`; поиск и статический frontend доступны.
- Тестовая MariaDB перезапущена через `docker restart`: сохранённый YouTube ID,
  название и строка сессии остались в БД. Это проверка перезапуска контейнера;
  долговечность Compose обеспечивается именованным volume.
- `mariadb-dump --single-transaction --routines --triggers` восстановлен в отдельную
  пустую `openmusic_restore_test`: сохранённый YouTube ID, название и запись
  `001_accounts_likes.sql` в `schema_migrations` восстановились.
- `npm run check`, `npm test` — успешно. Три файла, **25 JavaScript-тестов**:
  7 artwork-wave, 12 stream/player и 6 favorites. Проверены credentials/CSRF,
  порядок страниц, ошибки/401, постоянные ключи, отсутствие временных аудиоссылок,
  распознавание старых лайков и остановка незавершённого аудио при выходе.
- `tests/account-ui.mjs` — headless Chrome, desktop и mobile, **ответы API
  подменены**. Проверены приглашение гостя войти, восстановление YouTube и resolve
  по ID без поиска, ошибка `503` рядом с действием без ложного лайка,
  независимость лайка альбома, импорт только по нажатию, сохранность localStorage
  при частичной ошибке, повтор без дублей, очистка списков после выхода.
- `git diff --check` — успешно.

Один warning backend-тестов — deprecation Starlette TestClient/httpx из существующего
стека; ошибок тестов нет. Тесты с доступом к MariaDB требуют сетевого доступа
к loopback. Без TEST_DB_NAME интеграционные проверки намеренно пропускаются.

## Оставшаяся ручная приёмка

После настройки BotFather и HTTPS выполнить и записать фактические результаты:

1. Настоящий Telegram-вход аккаунта A, повторный вход и сохранение внутреннего ID.
2. Добавление и удаление демотрека, найденного YouTube-трека и альбома. Убедиться,
   что лайк альбома не меняет лайки его треков.
3. Обновление страницы, перезапуск backend/Compose и вход аккаунта A на втором
   устройстве: порядок и состав избранного совпадают. YouTube Play вызывает
   resolver по сохранённому ID и действительно воспроизводит звук без поиска.
4. Вход аккаунта B: избранное A отсутствует. Logout A, истечение и отзыв сессии:
   закрытый API отвечает `401`, данные A не отображаются.
5. Реальный сбой БД/сети во время лайка и импорта: видимая ошибка, прежнее состояние
   кнопки, сохранный старый ключ; после восстановления повтор без дублей.
6. На настоящем HTTPS проверить cookie Secure/HttpOnly/SameSite и отсутствие
   callback code/state и Telegram Secret в логах приложения/reverse proxy.

Шаблон записи в PR: URL окружения, дата, два обозначения аккаунтов без личных
идентификаторов, браузеры/устройства, фактический результат каждого пункта,
оставшиеся проблемы. Не прикладывать secrets, cookies, коды callback и токены.
