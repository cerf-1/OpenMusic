# ТЗ по рекомендациям в OpenMusic

Добавить похожие треки в очередь при запуске из Search и Liked Songs. Заполнить подборки на Home и Search рекомендациями по последнему лайкнутому треку.

## Источник рекомендаций

1. Переиспользовать на backend Python-парсер из `/home/gl/code/openmusic/music-matcher`. Вызов принимает исполнителя и название исходного трека и возвращает до 12 пар «исполнитель — трек» в порядке выдачи. Добавить Playwright и Chromium в окружение backend. [Music Matcher](https://musicmatcher.app/)
2. Найти совпадения по исполнителю и названию через существующий поиск YouTube Music. Сохранить порядок выдачи, исключить исходный трек и дубли, пропустить неподтверждённые совпадения. При воспроизведении использовать текущий resolver по `video_id`.
3. Для карточек взять артистов и альбомы из метаданных найденных треков. Использовать существующие страницы артистов. Сопоставление с релизом добавить в backend, так как текущий поиск не возвращает данные альбомов. Показывать только подтверждённые релизы с открываемой карточкой. Повторяющиеся альбомы и артистов показывать по одному разу.

Парсер работает в фоне с ограниченным временем ожидания. При сбое, таймауте или пустой выдаче показывать только доступные результаты. Поиск и воспроизведение продолжают работать.

## Очередь воспроизведения

- При запуске трека из Search, включая быстрый поиск и Made to discover, или из Liked Songs сразу начать обычное воспроизведение. В фоне запросить рекомендации по запущенному треку. Кнопка Play в Liked Songs использует первый трек списка.
- Собрать Up next из треков, добавленных вручную, и рекомендаций в таком порядке. При новом запуске из Search или Liked Songs заменить прежнюю автоматическую очередь. Применять ответ только к запуску, для которого он был запрошен.
- По окончании трека плеер продолжает воспроизведение по готовой очереди. Если очередь пуста, воспроизведение завершается. Переход к следующему треку из очереди использует уже собранный список.

## Подборки на Home и Search

Использовать последний добавленный лайк на трек текущего пользователя. Одна выдача Music Matcher наполняет все четыре блока.

| Где | Блок | Содержимое |
| --- | --- | --- |
| Home | On repeat | Похожие треки |
| Home | Artists to explore | Исполнители похожих треков |
| Home | Made for you | Альбомы похожих треков |
| Search | Made to discover | Похожие треки в начальном состоянии поиска |

При смене последнего лайка обновить подборки. Если пользователь снял последний лайк, использовать следующий по времени. Если лайкнутых треков нет или пользователь вышел из аккаунта, оставить блоки пустыми. Запуск трека из Search доступен и гостю.

## Удаление демоданных

Удалить из каталога приложения все встроенные тестовые треки, альбомы и исполнителей. Убрать ссылки на них из стартового экрана, библиотеки, очереди и других разделов. При открытии сохранённых лайков и плейлистов пропускать ссылки на удалённые демозаписи. Сохранить реальные лайки и пользовательские плейлисты с оставшимися треками в исходном порядке.

## Приёмка

1. Запустить трек из Search и из Liked Songs. Трек начинает играть сразу, похожие появляются в очереди, по окончании плеер переходит к следующему треку.
2. Быстро запустить трек A, затем трек B. Ответ для A не меняет очередь B. Добавленный вручную трек сохраняет приоритет.
3. Поставить лайк треку с подходящей выдачей. Все четыре блока показывают соответствующие треки, альбомы и артистов. Смена последнего лайка обновляет блоки, удаление всех лайков очищает их.
4. Проверить пустую выдачу и таймаут парсера. Поиск и плеер работают без демоданных. На новом аккаунте и после выхода подборки пусты, тестовые записи отсутствуют во всех разделах.
5. Закоммитить изменения в отдельную ветку `feature/`.
