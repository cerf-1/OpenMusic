# Firefox: облегчение стеклянного плеера

27 октября 2026. Ветка `codex/firefox-animation-performance`, база `875bc503`.
Изменения локальные: опубликованный Site и `main` не обновлялись.

## Диагноз и пределы уверенности

Жалоба: в Brave анимация плавная, в Firefox — сильные рывки.
Главные кандидаты в текущем коде:

- Живой `backdrop-filter: blur(24px) saturate(1.45)` на почти полноширинной
  фиксированной панели с округлением и составной маской края. При прокрутке
  меняется фон, который приходится фильтровать.
- Два круглых слоя волны: диаметр равен удвоенному расстоянию до дальнего угла.
  Они значительно выше самой панели, хотя почти вся их площадь обрезается.
  В проверке при viewport 1440×900 каждый слой имел размер 1400.33×1400.33 CSS px,
  а панель — высоту 113 px. DPR дополнительно увеличивает число физических пикселей.
- На hero, мобильной навигации, toast и кнопке закрытия также присутствовал blur;
  hover обложек сочетал transform с фильтром насыщенности.

Это обоснованная гипотеза по устройству эффектов, **не профиль Gecko**.
Firefox недоступен в подключённых браузерах этой среды. Нельзя утверждать,
что установлена конкретная ошибка WebRender или измерен рост FPS.
Web Audio не менялся; его вклад на устройстве пользователя ещё не исключён.
Индикаторы музыки уже используют transform, а не анимацию height.

Mozilla рекомендует небольшие анимированные поверхности и transform/opacity:
<https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Fundamentals>.
Эти свойства дают возможность композиции, но сами по себе не гарантируют её
стоимость. О дополнительных проходах backdrop-filter:
<https://webkit.org/blog/3632/introducing-backdrop-filters/>.

## Исправление

CSS `@supports (-moz-appearance: none)` включает адресную политику для Gecko.
Это намеренный обход для движка, а не проверка мощности устройства. UA не читается.

- Плеер сохраняет оттенок подборки, градиенты, блики, форму и чёткие контролы,
  но использует плотный материал без живого размытия фона и составной маски.
- Вместо огромных кругов два световых фронта расходятся от play/pause к краям.
  Каждый слой — 96 px шириной и высотой с панель. Анимируются transform/opacity.
  При 1440×900 площадь двух слоёв меньше примерно в 181 раз. Это отношение
  геометрических площадей, **не** измерение GPU-памяти, загрузки или FPS.
- В Gecko отключены остальные перечисленные backdrop-фильтры и hover-saturate
  у обложек; увеличение обложки осталось.
- Blink/WebKit сохраняют прежние CSS-эффекты, размеры кругов и keyframes.
- Сохранены reduced motion/transparency/contrast, отмена при повторном нажатии
  и pagehide, освобождение завершённых анимаций. Новых таймеров нет.
- Обновлены cache versions CSS/JS. `npm run check` теперь проверяет также
  `liquid-glass.js`.

## Что проверено

- `node --check`: app.js, audio.js, liquid-glass.js; `git diff --check`.
- Одноразовый Node harness, 12 случаев: идентичность keyframes и геометрии
  режима rings исходному коммиту; ограниченная площадь режима sweep; движение
  в обе стороны от кнопки; конечная длительность; play/pause, повторный запуск,
  pagehide, изменение предпочтений, очистка завершённых эффектов и отсутствие WAAPI.
- UI через cua_repl в доступном Chromium: 1440×900, 768×900 и 390×844;
  нет горизонтального переполнения. Play/pause, повторные нажатия, next,
  перемотка и громкость клавишами, mute, очередь, изменение оттенка — работают.
  Console errors/warnings отсутствуют.
- Политика Gecko проверена в отдельной копии dist в `/tmp`: только для QA
  условие @supports заменено на поддерживаемое Chromium. Проверены вычисленные
  blur/mask/shadow = none, sweep, размеры полос и компоновка. Это проверка
  fallback-ветки, **не запуск Firefox**. Такой подмены в исходниках нет.
- В обычной версии Chromium подтверждены `rings` и исходный blur(24px).

## Проверка на устройстве с Firefox

Из этого репозитория запустить:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

Открыть `http://localhost:4173` в Firefox. Проверить прокрутку, несколько play/pause,
затем воспроизведение в течение 30 секунд и смену трека. В Inspector у `.player`
должно быть `--glass-ripple: sweep`, у `::before` — `backdrop-filter: none`.

Для сравнения с базой можно создать отдельный checkout базового коммита и
обслуживать его на другом порту. Не сравнивать с устаревшим CSS из кеша.
Если рывки останутся, записать профиль Firefox с Graphics/Media для одинакового
сценария: в паузе, при прокрутке, при воспроизведении без действий, play/pause.
Это позволит отделить графическую нагрузку от Web Audio и проблем драйвера.
Без такого сравнения результат на реальном Gecko остаётся неподтверждённым.
