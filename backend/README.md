# Локальный резолвер OpenMusic

Техническая проба: API ищет запись через yt-dlp и возвращает ссылки на аудио и обложку. Для Web Audio сервер передаёт аудио выбранного трека потоком, без сохранения на диск. Ссылки на аудио временные.

## Запуск

Нужны Python 3.12, Deno в `PATH` и доступ к YouTube. Установите Deno по инструкции https://docs.deno.com/runtime/getting_started/installation/; yt-dlp использует его для EJS. Из каталога `openmusic/backend`:

```sh
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --host 127.0.0.1 --port 8000
```

В другом терминале из каталога `openmusic`:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

Откройте `http://127.0.0.1:4173`, перейдите в Search и отправьте название. Если браузер блокирует автоматический запуск, нажмите Play. Плеер использует прямой поток, а не демозвук при ошибке.

Примеры API:

```sh
curl -X POST http://127.0.0.1:8000/api/v1/resolve -H 'Content-Type: application/json' -d '{"query":"Daft Punk Get Lucky"}'
curl -X POST http://127.0.0.1:8000/api/v1/resolve -H 'Content-Type: application/json' -d '{"video_id":"4D7u5KF7SP8"}'
```

Для тестов: `pip install -r requirements-test.txt`, затем `python -m pytest -q test_resolver.py`; из корня проекта `node --test tests/stream.test.js`.

### Постраничный поиск

`POST /api/v1/search` принимает `{"query":"Daft Punk", "page":1}` (страницы 1–100).
Ответ: `{items:[{video_id,title,artist,duration_seconds,cover_link}],page,has_more}`.
Страница содержит до 10 записей; один дополнительный элемент нужен для `has_more`.
Поиск использует flat metadata и lazy playlist, без получения аудио каждого трека.
Следующие страницы запрашиваются только при нажатии Next; frontend сохраняет
просмотренные страницы в памяти вкладки и блокирует повторный поиск того же текста.
Нормализация повторов: регистр, крайние и повторяющиеся пробелы.
Аудио загружается через прежний `/api/v1/resolve` по `video_id` только при Play;
поиск больше не начинает воспроизведение автоматически.

Параметры yt-dlp ограничивают окно выдачи. При переходе на далёкую страницу
экстрактор может повторно пройти предыдущие upstream-страницы; весь каталог и
будущие страницы заранее не перебираются. Общее количество результатов не вычисляется.
Перезапустите локальный backend после обновления. Sites публикует только `dist/`;
Python API необходимо запускать отдельно, как и раньше.

### Обложки и ожидание Play

Лёгкая выдача YouTube Music может содержать только ID и название. Если картинки
нет, `/search` возвращает `https://i.ytimg.com/vi/<video_id>/hqdefault.jpg`;
frontend также поддерживает этот fallback для совместимости с предыдущим API.
Неизвестная длительность отображается как `—:—` до получения метаданных.
Frontend подготавливает поток только первого результата страницы в фоне;
Play использует тот же незавершённый запрос. Остальные потоки запрашиваются
при выборе трека. Загрузка показана внутри кнопки плеера и строки трека;
нажатие кнопки плеера отменяет намерение запуска. Плавающих сообщений нет.


31 октября: поиск сохраняет исполнителей, длительность и квадратные обложки из
исходных musicResponsiveListItemRenderer. Локальный адаптер заменяет только
YouTube Music search extractor внутри экземпляра yt-dlp, без глобальных патчей
и без resolve каждого видео. Используется внутренний метод закреплённой версии
2026.10.26; при обновлении yt-dlp проверяйте адаптер реальным поиском.
Если CDN-обложка недоступна, FE использует mqdefault.jpg (без встроенных
верхнего/нижнего полей hqdefault). Для новых метаданных **перезапустите API**;
одна публикация статического frontend Python-процесс не обновляет.


### Аудиореактивная обложка (31 октября)

Установите обновлённые requirements.txt и перезапустите API. `/resolve` дополнительно
возвращает `audio_path`: путь `/api/v1/audio/<handle>` для реального анализа звука.
Frontend предпочитает этот маршрут и использует `crossOrigin=anonymous` и AnalyserNode.
С прежним API аудио остаётся прямым, а контур не имитирует неизвестный бит.

GET поддерживает одиночные Range, ответ 206 и заголовки Content-Range/Length.
Разрешённые origins прежние localhost/127.0.0.1:4173. Маршрут не принимает URL
от клиента: случайный handle указывает только на проверенный Googlevideo URL,
полученный через резолвер. До 64 handles в памяти на час, до 6 одновременных
соединений; региональные redirects проверяются по тому же HTTPS allowlist,
максимум 3 перехода. Файлы и аудиоданные не кешируются/не сохраняются на диск.
Запускайте одним uvicorn worker: handles находятся в памяти процесса.
Статическая публикация Site не запускает этот Python API и не обновляет его.
